# GPIO — первые руки микроконтроллера

## История

Представьте, что вы написали идеальную программу.

Она успешно скомпилировалась. Без единой ошибки загрузилась в микроконтроллер. Процессор честно выполняет каждую инструкцию.

Но вокруг ничего не происходит.

Светодиод не загорается.

Кнопка никак не влияет на программу.

Реле не щёлкает.

Двигатель молчит.

Кажется, будто микроконтроллер просто не работает.

На самом деле работает. Просто он ещё не умеет общаться с внешним миром.

Процессор находится внутри корпуса микроконтроллера. Он не может напрямую коснуться светодиода, почувствовать нажатие кнопки или подать питание на двигатель. Между программой и реальным миром должен существовать мост.

Таким мостом являются выводы микроконтроллера — **GPIO**.

Именно с GPIO начинается практически каждый Embedded-проект. До тех пор, пока инженер не научится управлять обычной ножкой микроконтроллера, все остальные интерфейсы будут казаться магией.

---

# Постановка задачи

Наша первая цель проста.

Мы хотим научиться делать две вещи:

* включать светодиод;
* считывать нажатие кнопки.

На первый взгляд задача кажется элементарной.

Но именно в ней скрывается фундамент всей Embedded-разработки.

Поняв GPIO, вы поймёте принцип работы практически любой периферии микроконтроллера.

---

# Что такое GPIO

GPIO расшифровывается как **General Purpose Input/Output** — вывод общего назначения.

Это универсальная ножка микроконтроллера, которую можно настроить под текущую задачу.

Сегодня она может работать как выход и включать светодиод.

Через минуту — стать входом и читать состояние кнопки.

Позже — использоваться как часть интерфейса UART, SPI или I²C.

Одни и те же ножки способны выполнять разные роли. Именно поэтому перед использованием их необходимо правильно настроить.

---

# Простое объяснение

Представьте человека, сидящего в абсолютно тёмной комнате.

У него есть мозг.

Он умеет думать.

Может принимать решения.

Но он не видит происходящее снаружи и не способен ни до чего дотянуться.

Теперь представьте, что ему дали руки.

Теперь он может:

* нажать кнопку;
* включить лампу;
* открыть дверь;
* почувствовать прикосновение.

Для микроконтроллера такими руками являются GPIO.

```
          Программа

              │

          Процессор

              │

        GPIO (руки)

     ┌──────┼──────┐
     │      │      │
 Светодиод Кнопка Датчик
```

Процессор принимает решения.

GPIO позволяют этим решениям попасть во внешний мир.

---

# Что происходит внутри микроконтроллера

Каждая ножка подключена к внутренней цифровой логике.

Перед работой необходимо определить:

* будет ли ножка входом;
* будет ли ножка выходом;
* нужно ли подать высокий уровень;
* нужно ли считать текущее состояние ножки.

Для этого микроконтроллер использует специальные регистры.

---

# Регистры GPIO

Для большинства AVR используются три основных регистра.

## DDRx

Data Direction Register.

Определяет направление работы ножки.

```
0 — вход

1 — выход
```

Например:

```
DDRB |= (1 << PB0);
```

После выполнения этой команды ножка PB0 начинает работать как выход.

---

## PORTx

Поведение регистра зависит от режима работы ножки.

Если ножка настроена как выход:

```
0 — подать LOW

1 — подать HIGH
```

Если ножка настроена как вход:

```
0 — подтяжка выключена

1 — включить внутренний pull-up
```

Именно поэтому один и тот же регистр используется в двух разных ситуациях.

---

## PINx

Позволяет узнать текущее состояние ножки.

Например:

```
if (PIND & (1 << PD2))
```

означает:

> прочитать состояние ножки PD2.

---

# Почему используются маски

Допустим, порт B содержит сразу восемь устройств.

```
PB0 — светодиод

PB1 — сервопривод

PB2 — реле

PB3 — свободен

...
```

Если выполнить

```
PORTB = 0x01;
```

то остальные семь битов будут полностью переписаны.

Это может выключить сервопривод, реле или любое другое устройство.

Поэтому практически всегда используют маски.

```
PORTB |= (1 << PB0);
```

Такая запись изменяет только нужный бит.

Все остальные остаются без изменений.

---

# Подключение кнопки

Кнопка — это обычный переключатель.

Если просто подключить её к ножке микроконтроллера, то при отсутствии нажатия вход окажется "висящим".

Его состояние станет случайным.

Программа начнёт видеть ложные нажатия.

Поэтому используют подтягивающий резистор.

```
      +5V

       │

   Pull-up

       │

PD2 ───┴──── Кнопка ─── GND
```

Пока кнопка отпущена,

на входе присутствует логическая единица.

После нажатия ножка соединяется с землёй.

Получается логический ноль.

Именно поэтому во многих проектах можно встретить запись

```c
if (!(PIND & (1 << PD2)))
```

Она буквально означает:

> если на ножке появился логический ноль — кнопка нажата.

# Проектирование драйвера

Даже для обычного светодиода не стоит писать код напрямую в `main()`.

Лучше сразу привыкать разделять проект на модули.

Например:

```
drivers/

    led/

        led.c

        led.h
```

Внутри драйвера можно скрыть всю работу с регистрами.

Тогда основной код будет выглядеть значительно проще.

```
Led_On();

Led_Off();

Led_Toggle();
```

Если позже микроконтроллер изменится, достаточно будет переписать только драйвер.

Остальная программа останется прежней.

Именно так постепенно строится хорошая архитектура Embedded-проекта.

# Типичные ошибки

**Первая ошибка**

Забыли перевести ножку в режим выхода.

Программа меняет `PORT`, но светодиод не загорается.

---

**Вторая ошибка**

Используют

```
PORTB = ...
```

вместо

```
PORTB |= ...
```

или

```
PORTB &= ...
```

В результате случайно изменяются остальные выводы порта.

---

**Третья ошибка**

Не включили pull-up.

Вход начинает случайным образом менять своё состояние.

---

**Четвёртая ошибка**

Подключили два выхода друг к другу.

Например,

один вывод выдаёт HIGH,

второй LOW.

Возникает большой ток, который может повредить микроконтроллер.

---

# Практическое применение

Практически любое устройство начинается с GPIO.

Через него подключаются:

* светодиоды;
* кнопки;
* реле;
* пищалки;
* транзисторы;
* оптопары;
* энкодеры;
* драйверы двигателей;
* дисплеи;
* датчики.

Даже когда позже вы будете изучать UART, SPI, I²C или PWM, всё равно будете работать с теми же физическими ножками микроконтроллера. Просто они будут выполнять уже специализированную функцию.

---

# Что должен уметь инженер

После этой главы вы должны понимать:

* что такое GPIO и зачем он нужен;
* чем отличаются вход и выход;
* зачем нужен pull-up;
* для чего используются регистры `DDRx`, `PORTx` и `PINx`;
* почему применяются побитовые операции и маски;
* почему драйверы GPIO лучше выносить в отдельный модуль.

---

# Практическое задание

1. Подключите светодиод к выводу PB0 и заставьте его загореться.
2. Подключите кнопку к PD2 с использованием внутреннего pull-up.
3. Сделайте так, чтобы каждое нажатие кнопки переключало состояние светодиода.
4. Попробуйте специально заменить побитовые операции на `PORTB = ...` и понаблюдайте, какие проблемы могут возникнуть при использовании нескольких выводов одного порта.
