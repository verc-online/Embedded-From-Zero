# UART

## 1. История

На первых этапах работы с микроконтроллером мы почти ничего не видим.

Светодиод может моргнуть. Серва может повернуться. Кнопка может сработать. Но если внутри программы что-то пошло не так, микроконтроллер молчит.

Мы не знаем:

* дошёл ли код до нужного места;
* какое значение лежит в переменной;
* прочиталось ли время из RTC;
* сработало ли условие;
* почему устройство ведёт себя не так, как мы ожидали.

Можно пытаться всё проверять светодиодом:

```text
моргнул один раз  — программа стартовала
моргнул два раза — ошибка
моргнул три раза — другая ошибка
```

Но это быстро превращается в гадание.

Embedded-разработчику нужен способ услышать микроконтроллер.

И здесь появляется UART.

UART позволяет микроконтроллеру отправлять наружу обычный текст:

```text
Feeder started
Servo opened
RTC read error
Current time: 12:30
```

Теперь микроконтроллер уже не чёрный ящик. Он может сообщать, что происходит внутри программы.

---

## 2. Постановка задачи

Нам нужно научить ATmega8 отправлять текстовые сообщения через UART.

Для первой версии драйвера мы реализуем только передачу данных:

```c
void UART_Init(void);
void UART_SendChar(char c);
void UART_SendString(const char* str);
```

Наша задача:

```text
1. Настроить UART.
2. Установить скорость передачи.
3. Выбрать формат кадра.
4. Включить передатчик.
5. Отправить один символ.
6. Отправить строку.
```

В нашем проекте UART нужен не как отдельная «красивая тема», а как практический инструмент.

Он поможет нам отлаживать кормушку:

```text
Feeder init
Button pressed
Servo opened
Servo closed
RTC read OK
Schedule match
```

То есть UART становится голосом микроконтроллера.

## 3. Простое объяснение

GPIO — это просто ножка, которой мы можем сказать:

```text
будь нулём
будь единицей
```

UART — это уже не просто ножка. Это договор о передаче данных.

Два устройства заранее договариваются:

```text
с какой скоростью говорить;
сколько бит данных передавать;
будет ли проверка чётности;
сколько стоп-битов использовать.
```

Например, запись:

```text
9600 8N1
```

означает:

```text
9600 — скорость передачи;
8    — 8 бит данных;
N    — no parity, без проверки чётности;
1    — 1 стоп-бит.
```

UART передаёт данные последовательно.

Это значит, что байт не уходит сразу по восьми проводам. Он уходит по одному проводу, бит за битом.

```text
Не так:

bit0 bit1 bit2 bit3 bit4 bit5 bit6 bit7
 |    |    |    |    |    |    |    |
провод провод провод провод ...

А так:

TX ─── bit0 ─ bit1 ─ bit2 ─ bit3 ─ bit4 ─ bit5 ─ bit6 ─ bit7
```

Обычно используются два пина:

```text
TX — transmit, передача;
RX — receive, приём.
```

Если микроконтроллер отправляет данные в компьютер, используется его пин `TX`.

Если микроконтроллер принимает команды от компьютера, используется его пин `RX`.

## 4. Что происходит внутри микроконтроллера

Когда мы вызываем:

```c
UART_SendChar('A');
```

мы не передаём букву вручную.

Программа просто кладёт байт в специальный регистр данных UART:

```c
UDR = 'A';
```

Символ `'A'` в памяти — это число:

```text
'A' = 0x41 = 0b01000001
```

После записи в `UDR` аппаратный UART сам делает всю временную работу.

Он формирует кадр:

```text
start bit
8 data bits
stop bit
```

Схематично:

```text
idle   start   data bits              stop
  1      0     b0 b1 b2 b3 b4 b5 b6 b7  1
```

Для символа `'A'`:

```text
'A' = 0b01000001
```

UART отправляет младший бит первым:

```text
start  b0 b1 b2 b3 b4 b5 b6 b7  stop
  0     1  0  0  0  0  0  1  0    1
```

Физически на пине `TX` появляются логические уровни `0` и `1`, выдержанные по времени согласно выбранной скорости.

Важно не путать UART с PWM.

PWM — это периодический сигнал, где мы управляем скважностью.

UART — это последовательность битов, в которой закодированы данные.

Похожесть только в одном: в обоих случаях аппаратный блок микроконтроллера сам управляет пином по времени, освобождая процессор от ручного переключения.

## 5. Регистры

Для настройки UART в ATmega8 нам понадобятся несколько регистров.

### UBRRH и UBRRL

Это регистры скорости передачи:

```text
UBRRH — старшая часть значения UBRR;
UBRRL — младшая часть значения UBRR.
```

`UBRR` определяет, с какой скоростью UART будет передавать данные.

Для обычного режима формула такая:

```text
UBRR = F_CPU / (16 * BAUD) - 1
```

Но у нас:

```text
F_CPU = 1 MHz
BAUD  = 9600
```

В обычном режиме ошибка получается слишком большой.

Поэтому мы включаем режим двойной скорости `U2X`.

Для него формула:

```text
UBRR = F_CPU / (8 * BAUD) - 1
```

Подставляем значения:

```text
UBRR = 1000000 / (8 * 9600) - 1
UBRR ≈ 12
```

Поэтому в коде:

```c
UBRRH = 0;
UBRRL = 12;
```

---

### UCSRA

В `UCSRA` находятся флаги состояния UART.

Нас интересуют два бита:

```text
U2X  — режим двойной скорости;
UDRE — USART Data Register Empty.
```

`U2X` мы включаем при инициализации:

```c
UCSRA |= (1 << U2X);
```

`UDRE` показывает, свободен ли регистр данных `UDR`.

Если `UDRE = 1`, значит буфер передачи пуст, и туда можно записать новый байт.

```c
while (!(UCSRA & (1 << UDRE)))
{
    // ждём освобождения UDR
}
```

Без этой проверки можно попытаться записать новый байт слишком рано.

Тогда данные могут потеряться или передача станет некорректной.

---

### UCSRB

В `UCSRB` включается передатчик и приёмник.

Для передачи нужен бит:

```text
TXEN — Transmitter Enable.
```

Для приёма нужен бит:

```text
RXEN — Receiver Enable.
```

В первой версии драйвера нам достаточно передачи:

```c
UCSRB = (1 << TXEN);
```

Если позже добавим приём команд, можно будет включить и `RXEN`.

---

### UCSRC

В `UCSRC` настраивается формат кадра:

```text
количество бит данных;
количество стоп-битов;
проверка чётности.
```

Нам нужен стандартный формат:

```text
8 бит данных;
без проверки чётности;
1 стоп-бит.
```

То есть:

```text
UCSZ1 = 1
UCSZ0 = 1
USBS  = 0
UPM1  = 0
UPM0  = 0
```

В ATmega8 есть важная особенность: `UCSRC` и `UBRRH` имеют общий адрес ввода-вывода.

Поэтому при записи в `UCSRC` нужно выставить бит `URSEL`.

```text
URSEL = 1 → обращаемся к UCSRC
URSEL = 0 → обращаемся к UBRRH
```

Поэтому настройка выглядит так:

```c
UCSRC = (1 << URSEL)
      | (1 << UCSZ1)
      | (1 << UCSZ0);
```

## 6. Проектирование драйвера

UART — это периферия, поэтому мы оформляем его как отдельный драйвер.

Структура:

```text
drivers/
  uart/
    uart.h
    uart.c
```

Внешнему коду не нужно знать, какие регистры мы настраиваем внутри.

`main.c` должен видеть только простой интерфейс:

```c
void UART_Init(void);
void UART_SendChar(char c);
void UART_SendString(const char* str);
```

Это и есть смысл драйвера.

Мы прячем работу с регистрами внутри `uart.c`, а наружу отдаём понятные функции.

```text
main.c
  |
  | UART_SendString("Feeder started");
  v
uart.c
  |
  | работа с UCSRA, UCSRB, UCSRC, UBRR, UDR
  v
железо UART
  |
  v
TX pin
```

Такой подход делает проект проще.

Если позже мы поменяем скорость, добавим приём или перенесём код на другой микроконтроллер, основной код проекта не должен сильно измениться.

## 7. Реализация

Файл `uart.h`:

```c
#ifndef UART_H_
#define UART_H_

void UART_Init(void);
void UART_SendChar(char c);
void UART_SendString(const char* str);

#endif
```

Файл `uart.c`:

```c
#include <avr/io.h>
#include "uart.h"

#define UART_UBRR_VALUE 12

void UART_Init(void)
{
    // 9600 baud при F_CPU = 1 MHz, U2X = 1
    UBRRH = 0;
    UBRRL = UART_UBRR_VALUE;

    // Double Speed Mode
    UCSRA |= (1 << U2X);

    // Включаем передатчик
    UCSRB = (1 << TXEN);

    // UCSRC и UBRRH имеют общий адрес в ATmega8.
    // URSEL = 1 означает: записываем именно в UCSRC.
    // UCSZ1 = 1 и UCSZ0 = 1 означает: 8 бит данных.
    // USBS = 0 означает: 1 стоп-бит.
    // UPM1 = 0 и UPM0 = 0 означает: без проверки чётности.
    UCSRC = (1 << URSEL)
          | (1 << UCSZ1)
          | (1 << UCSZ0);
}

void UART_SendChar(char c)
{
    while (!(UCSRA & (1 << UDRE)))
    {
        // Ждём освобождения регистра UDR
    }

    UDR = c;
}

void UART_SendString(const char* str)
{
    while (*str != '\0')
    {
        UART_SendChar(*str);
        str++;
    }
}
```

Проверка в `main.c`:

```c
#include <avr/io.h>
#include "drivers/uart/uart.h"

int main(void)
{
    UART_Init();

    UART_SendString("UART started\r\n");

    while (1)
    {
    }
}
```

Ожидаемый вывод в терминале:

```text
UART started
```

## 8. Разбор архитектуры

В этой версии драйвер очень простой.

Он умеет только отправлять символы и строки.

Но даже такая простая версия уже полезна.

Теперь в любом месте программы можно написать:

```c
UART_SendString("Servo opened\r\n");
```

И увидеть, дошёл ли код до нужного места.

Например, в логике кормушки можно временно добавить:

```c
UART_SendString("Feeder request\r\n");
```

или:

```c
UART_SendString("Schedule matched\r\n");
```

Это сильно помогает при отладке.

Без UART мы видим только внешнее поведение устройства.

С UART мы начинаем видеть внутреннее состояние программы.

Архитектурно UART можно использовать как отдельный слой отладки:

```text
app/
  feeder.c
  scheduler.c

drivers/
  uart.c
  servo.c
  timer.c
```

При этом `feeder.c` не должен знать, как именно настроены регистры UART.

Он просто вызывает функцию драйвера.

## 9. Типичные ошибки

### Ошибка 1. Забыть включить TXEN

Если не включить передатчик:

```c
UCSRB = (1 << TXEN);
```

UART не будет отправлять данные.

Код может выглядеть правильным, но на пине `TX` ничего не появится.

---

### Ошибка 2. Неправильная скорость

Если микроконтроллер настроен на одну скорость, а терминал на другую, текст будет испорчен.

Например:

```text
микроконтроллер: 9600
терминал:       19200
```

В результате можно увидеть мусор вместо текста:

```text
þxø??@#
```

UART требует, чтобы обе стороны договорились о скорости.

---

### Ошибка 3. Не включить U2X при F_CPU = 1 MHz

При `F_CPU = 1 MHz` и `9600 baud` обычный режим даёт слишком большую ошибку.

Поэтому мы включаем:

```c
UCSRA |= (1 << U2X);
```

И используем:

```c
UBRRL = 12;
```

---

### Ошибка 4. Записать в UDR без проверки UDRE

Нельзя просто постоянно писать:

```c
UDR = c;
```

Перед этим нужно убедиться, что буфер свободен:

```c
while (!(UCSRA & (1 << UDRE)))
{
}
```

Иначе можно потерять данные.

---

### Ошибка 5. Забыть URSEL при настройке UCSRC

Для ATmega8 это особенно важно.

Неправильно:

```c
UCSRC = (1 << UCSZ1) | (1 << UCSZ0);
```

Правильно:

```c
UCSRC = (1 << URSEL)
      | (1 << UCSZ1)
      | (1 << UCSZ0);
```

Без `URSEL` запись может попасть не в тот регистр.

---

### Ошибка 6. Ожидать, что строка сама знает свою длину

В C строка заканчивается символом:

```c
'\0'
```

Поэтому `UART_SendString()` идёт по указателю до нулевого символа:

```c
while (*str != '\0')
{
    UART_SendChar(*str);
    str++;
}
```

Если строка не завершена `'\0'`, функция может уйти читать чужую память.

## 10. Практическое применение

UART полезен почти в каждом embedded-проекте.

В нашем проекте кормушки его можно использовать для отладки:

```text
устройство включилось;
кнопка нажата;
серва открылась;
серва закрылась;
время считано из RTC;
наступило время кормления;
произошла ошибка чтения.
```

Например:

```c
UART_SendString("Feeder started\r\n");
```

Или:

```c
UART_SendString("Button pressed\r\n");
```

Позже через UART можно не только отправлять сообщения, но и принимать команды.

Например:

```text
OPEN
CLOSE
TIME?
FEED
```

Тогда компьютер сможет управлять микроконтроллером.

Но это следующий уровень.

Сначала важно понять передачу.

## 11. Что должен уметь инженер

После этой темы инженер должен уметь:

```text
объяснить, зачем нужен UART;
отличить UART от GPIO и PWM;
объяснить, что означает 9600 8N1;
рассчитать или проверить значение UBRR;
понимать, зачем нужен U2X;
настроить TX;
отправить один символ;
отправить строку;
понимать роль UDR и UDRE;
читать соответствующий раздел Datasheet.
```

Главное — не запомнить конкретное число `12`.

Главное — понимать, откуда оно взялось и почему без правильной скорости UART не сможет нормально общаться с внешним устройством.

## 12. Практическое задание

1. Создать файлы:

```text
drivers/uart/uart.h
drivers/uart/uart.c
```

2. Реализовать функции:

```c
void UART_Init(void);
void UART_SendChar(char c);
void UART_SendString(const char* str);
```

3. В `main.c` отправить строку:

```c
UART_SendString("UART started\r\n");
```

4. Проверить вывод в терминале или Proteus.

5. Добавить несколько сообщений в проект кормушки:

```text
Feeder init
Button pressed
Servo opened
Servo closed
```

6. Убедиться, что сообщения помогают понять ход выполнения программы.

Дополнительное задание:

реализовать функцию:

```c
void UART_SendLine(const char* str);
```

Она должна отправлять строку и автоматически добавлять перевод строки:

```c
\r\n
```

## Итог

UART — это первый интерфейс, который позволяет микроконтроллеру не просто выполнять программу, а сообщать разработчику, что происходит внутри.

До UART мы могли только наблюдать внешнее поведение устройства.

После UART мы можем видеть сообщения, значения, ошибки и этапы выполнения программы.

Для embedded-разработчика это важный шаг.

Потому что настоящий инженер не гадает, что происходит в микроконтроллере.

Он заставляет устройство говорить.
