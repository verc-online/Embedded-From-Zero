# PWM — когда микроконтроллер начинает работать сам

## История

Когда мы только начали изучать микроконтроллеры, всё казалось достаточно простым.

Нужно включить светодиод? Записываем единицу в регистр порта.

Нужно выключить? Записываем ноль.

Если хочется помигать светодиодом, можно написать:

```c
PORTB |= (1 << PB0);
_delay_ms(500);

PORTB &= ~(1 << PB0);
_delay_ms(500);
```

Работает? Работает.

Но что делать, если теперь нужно не просто включать и выключать светодиод, а плавно изменять его яркость? Или управлять скоростью двигателя? Или повернуть сервопривод на определённый угол?

Можно попробовать продолжить использовать задержки.

```c
PORTB |= (1 << PB1);
_delay_us(1500);

PORTB &= ~(1 << PB1);
_delay_us(18500);
```

И повторять этот цикл бесконечно.

Такой код действительно будет работать. Но возникает серьёзная проблема.

Пока процессор занимается генерацией импульсов, он практически ничем другим заниматься не может.

Он не читает кнопки.

Не работает с часами.

Не обрабатывает UART.

Не выполняет никакой другой полезной работы.

Получается, что весь микроконтроллер занят одной-единственной задачей — переключением одного вывода.

Инженеры быстро поняли, что процессор не должен выполнять такую однообразную работу самостоятельно. Гораздо разумнее поручить её специализированному аппаратному блоку.

Так появился PWM.

---

# Что такое PWM

PWM (Pulse Width Modulation) — это широтно-импульсная модуляция.

Несмотря на сложное название, идея очень простая.

Микроконтроллер быстро переключает вывод между логическим нулём и логической единицей.

При этом изменяется не напряжение, а время, которое вывод находится в состоянии логической единицы.

Например:

```text
████████________
```

или

```text
████____________
```

или

```text
████████████____
```

Напряжение всегда остаётся одинаковым.

Либо:

```
0 В
```

либо:

```
5 В
```

Никаких промежуточных значений GPIO выдавать не умеет.

Но если переключение происходит очень быстро, устройство начинает воспринимать среднее значение сигнала.

Для светодиода это означает изменение яркости.

Для двигателя — изменение средней мощности.

Для сервопривода — передачу команды на определённый угол.

---

# Где используется PWM

Практически в каждом современном устройстве.

Например:

* регулировка яркости светодиодов;
* управление скоростью электродвигателей;
* управление вентиляторами;
* питание нагревательных элементов;
* генерация простых аналоговых сигналов;
* управление сервоприводами.

В нашем проекте PWM используется именно для управления сервоприводом.

---

# Основные параметры PWM

Любой PWM-сигнал можно описать тремя параметрами.

## Период

Период — это время одного полного цикла.

```text
████████________
```

Вся эта последовательность — один период.

После его окончания начинается следующий.

---

## Частота

Частота показывает, сколько таких периодов происходит за одну секунду.

Она обратно пропорциональна периоду.

Чем меньше период, тем выше частота.

---

## Коэффициент заполнения

Коэффициент заполнения показывает, какую часть периода вывод находится в состоянии логической единицы.

Например

```text
████____
```

примерно соответствует заполнению 50%.

А

```text
████████____
```

будет иметь уже гораздо большее заполнение.

Для светодиода увеличение коэффициента заполнения означает увеличение яркости.

Для сервопривода важен уже не сам процент, а абсолютная длительность импульса.

---

# Почему PWM генерирует именно таймер

В какой-то момент разработчики микроконтроллеров задали себе простой вопрос.

Если процессор лишь бесконечно включает и выключает один вывод, зачем вообще нагружать его этой работой?

Ответ оказался очевидным.

Эту задачу можно поручить таймеру.

Таймер умеет самостоятельно считать время.

Остаётся только научить его переключать вывод в нужные моменты.

Именно это и делает аппаратный PWM.

Процессор всего один раз сообщает таймеру параметры работы.

После этого таймер начинает самостоятельно формировать сигнал.

Процессор в это время может выполнять совершенно другие задачи.

Это одна из важнейших идей Embedded-разработки.

Мы не заставляем процессор постоянно выполнять однообразную работу.

Мы используем встроенную периферию микроконтроллера.

---

# Что происходит внутри микроконтроллера

После настройки PWM внутри микроконтроллера происходит примерно следующее.

```text
                     CPU
                      │
        записывает OCR1A и ICR1
                      │
                      ▼
             +----------------+
             |     Timer1     |
             |                |
             |  TCNT1         |
             | Comparator     |
             +----------------+
                      │
          формирует PWM сигнал
                      │
                      ▼
     Альтернативная функция вывода
                      │
                      ▼
                    PB1
                      │
                      ▼
                 Сервопривод
```

Обратите внимание на одну интересную особенность.

После записи значений процессор практически перестаёт участвовать в генерации сигнала.

Всю дальнейшую работу выполняет аппаратная логика таймера.

Именно поэтому PWM практически не нагружает процессор.

---

# Почему Timer1 управляет выводом PB1

Раньше мы управляли выводом через регистр PORTB.

Но после включения режима PWM ситуация меняется.

PB1 перестаёт быть обычным GPIO.

Теперь этот вывод подключается к выходу Timer1 через альтернативную функцию.

Можно представить это так.

```text
До настройки

CPU
 │
 ▼
PORTB
 │
 ▼
PB1


После настройки PWM

Timer1
 │
 ▼
PB1
```

Именно поэтому после включения PWM нам больше не нужно самостоятельно изменять состояние вывода.

Это делает сам таймер.

---

# Регистры Timer1

Для управления PWM мы использовали всего несколько основных регистров.

## TCNT1

Это счётчик таймера.

Он постоянно увеличивается.

```
0

↓

1

↓

2

↓

...

↓

TOP

↓

0
```

---

## ICR1

В режиме Fast PWM Mode 14 именно этот регистр задаёт верхнюю границу счётчика.

Другими словами, он определяет период PWM.

В нашем проекте:

```text
ICR1 = 2500
```

что соответствует периоду около 20 мс.

---

## OCR1A

Этот регистр определяет момент, когда необходимо изменить состояние вывода.

Пока

```
TCNT1 < OCR1A
```

на выводе находится логическая единица.

Когда счётчик достигает значения OCR1A, таймер автоматически переводит вывод в логический ноль.

Именно поэтому изменение OCR1A приводит к изменению ширины импульса.

---

# Почему мы использовали Fast PWM Mode 14

У Timer1 существует несколько режимов PWM.

Мы выбрали Fast PWM Mode 14 не случайно.

Его главное преимущество заключается в разделении обязанностей.

ICR1 отвечает только за период.

OCR1A отвечает только за ширину импульса.

Благодаря этому можно свободно изменять положение сервопривода, не затрагивая частоту сигнала.

Именно поэтому данный режим идеально подходит для управления сервоприводами.

---

# Почему для сервопривода используется период 20 мс

Может показаться, что период 20 мс был выбран произвольно.

На самом деле это не так.

Такой сигнал ожидает сама электроника сервопривода.

Другими словами, это требование производителя устройства.

Наша задача — сформировать именно тот сигнал, который сервопривод умеет понимать.

---

# Архитектура нашего драйвера

Работа драйвера выглядит очень просто.

```text
Servo_SetAngle()

↓

вычислить OCR1A

↓

записать новое значение

↓

Timer1 самостоятельно формирует PWM
```

Получается, что функция управления сервоприводом не генерирует импульсы самостоятельно.

Она лишь сообщает таймеру новую длительность импульса.

Всю остальную работу выполняет аппаратная периферия микроконтроллера.

---

# Типичные ошибки

Новички часто пытаются формировать PWM при помощи `_delay()`.

Такой подход работает только в самых простых примерах, но полностью блокирует процессор.

Вторая распространённая ошибка — считать, что PWM создаёт аналоговое напряжение.

На самом деле вывод по-прежнему выдаёт только логический ноль или логическую единицу.

Меняется лишь длительность этих состояний.

Ещё одна ошибка — использовать восьмибитный таймер там, где требуется длинный период. Для управления сервоприводом это невозможно, поскольку счётчик Timer0 не способен отсчитать необходимое количество тиков при выбранных настройках.

# Практическое применение

После изучения PWM вы уже умеете:

* регулировать яркость светодиодов;
* управлять сервоприводами;
* изменять скорость двигателей;
* понимать принцип работы аппаратной периферии микроконтроллера.

Именно с этого момента становится заметно, что процессор далеко не всегда выполняет всю работу самостоятельно.

Грамотная Embedded-разработка строится на использовании специализированных аппаратных модулей.
