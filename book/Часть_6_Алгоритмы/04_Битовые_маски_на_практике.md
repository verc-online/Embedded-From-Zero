# 04. Битовые маски на практике

## История

Когда я впервые открыл Datasheet на ATmega8, меня встретили десятки непонятных записей.

```c
DDRB |= (1 << PB0);

TCCR1A |= (1 << COM1A1);

TWCR |= (1 << TWEN);

UCSRB |= (1 << TXEN);
```

Сначала казалось, что это какие-то странные заклинания, которые нужно просто запомнить.

Почему везде используется `1 <<`?

Почему нельзя просто записать число?

Почему постоянно встречаются операции `|=`, `&=`, `~`?

Лишь после нескольких реализованных драйверов стало понятно, что во всех этих примерах используется один и тот же принцип.

Мы не записываем числа.

Мы управляем отдельными битами регистров.

---

# Постановка задачи

Научиться изменять только нужные биты регистра, не затрагивая остальные.

Именно для этого используются битовые маски.

---

# Простое объяснение

Представьте комнату с восемью лампочками.

Каждая лампочка имеет собственный выключатель.

```text
[7] [6] [5] [4] [3] [2] [1] [0]
```

Если нужно включить только третью лампу, совсем не обязательно заново выставлять состояние всех остальных.

Достаточно изменить один нужный выключатель.

Именно так работают регистры микроконтроллера.

Каждый бит отвечает за отдельную функцию.

---

# Что происходит внутри микроконтроллера

Практически все настройки микроконтроллера находятся в регистрах.

Каждый регистр состоит из восьми бит.

```text
7 6 5 4 3 2 1 0
+-+-+-+-+-+-+-+-+
| | | | | | | | |
+-+-+-+-+-+-+-+-+
```

Очень часто каждый бит имеет собственное назначение.

Например:

* включает модуль;
* выбирает режим работы;
* разрешает прерывание;
* подключает внутреннюю подтяжку;
* запускает передачу данных.

Изменяя один бит, мы управляем одной функцией микроконтроллера.

---

# Почему нельзя записывать готовые числа

Представим, что регистр уже содержит важные настройки.

```text
00110110
```

Если записать новое значение:

```text
00000100
```

мы случайно изменим остальные биты.

Вместе с нужной настройкой могут отключиться таймер, UART или другое оборудование.

Поэтому в Embedded почти никогда не записывают регистр целиком, если не требуется полностью изменить его конфигурацию.

Вместо этого изменяют только нужные биты.

---

# Включение бита

Самая распространённая операция.

```c
PORTB |= (1 << PB0);
```

Что происходит?

```text
1 << PB0

00000001
```

Получается маска, в которой установлен только один бит.

Операция `|=` устанавливает этот бит в единицу.

Все остальные остаются без изменений.

Именно поэтому такой способ безопасен.

---

# Сброс бита

Чтобы очистить бит, используется другая операция.

```c
PORTB &= ~(1 << PB0);
```

Сначала создаётся маска.

```text
00000001
```

Затем она инвертируется.

```text
11111110
```

После этого операция `&=` оставляет остальные биты без изменений, а нужный бит сбрасывает в ноль.

---

# Проверка бита

Часто необходимо узнать состояние входного вывода.

Например:

```c
if (PIND & (1 << PD2))
```

Происходит следующее.

```text
PIND

10100100

Маска

00000100

↓

10100100
&
00000100

↓

00000100
```

Если результат не равен нулю, значит соответствующий бит установлен.

Именно таким способом мы считывали состояние кнопки.

---

# Где мы использовали битовые маски

Во время разработки PetFeeder битовые маски встречались буквально в каждом драйвере.

## GPIO

```c
DDRB |= (1 << PB0);

PORTD |= (1 << PD2);
```

Настройка направления вывода и внутренней подтяжки.

---

## Timer

```c
TIMSK |= (1 << TOIE0);
```

Разрешение прерывания таймера.

---

## PWM

```c
TCCR1A |= (1 << COM1A1);

TCCR1B |= (1 << WGM13);
```

Настройка режима работы Timer1.

---

## UART

```c
UCSRB |= (1 << TXEN);

UCSRB |= (1 << RXEN);
```

Включение передатчика и приёмника.

---

## I²C

```c
TWCR |= (1 << TWEN);
```

Включение контроллера TWI.

---

## SPI

```c
SPCR |= (1 << SPE);

SPCR |= (1 << MSTR);
```

Включение SPI и выбор режима Master.

---

Получается интересная закономерность.

Хотя драйверы совершенно разные, способ настройки у них абсолютно одинаковый.

Меняются только регистры и названия битов.

---

# Архитектура решения

Во время работы с регистрами мы придерживались простого правила.

```text
Datasheet
     │
     ▼
Регистр
     │
     ▼
Нужный бит
     │
     ▼
Битовая маска
     │
     ▼
Изменение регистра
```

Мы никогда не использовали "магические числа".

Вместо этого всегда обращались к именам битов, определённым в библиотеке `<avr/io.h>`.

Так код становится понятнее и проще в сопровождении.

---

# Типичные ошибки

### Использование магических чисел

Плохо:

```c
PORTB = 32;
```

Через неделю уже невозможно понять, почему именно 32.

---

### Полная перезапись регистра

Если изменить весь регистр, можно случайно отключить другие функции.

---

### Неправильное использование оператора `=`

Очень частая ошибка:

```c
PORTB = (1 << PB0);
```

Вместо установки одного бита происходит полная перезапись регистра.

---

### Игнорирование Datasheet

Нельзя угадывать, какой бит за что отвечает.

Ответ всегда находится в документации на микроконтроллер.

---

# Практическое применение

Битовые маски используются практически во всех Embedded-проектах.

С их помощью настраиваются:

* GPIO;
* таймеры;
* UART;
* SPI;
* I²C;
* ADC;
* прерывания;
* режимы энергосбережения.

Практически любая настройка микроконтроллера в конечном итоге сводится к изменению нескольких битов регистров.

---

# Что должен уметь инженер

После этой главы вы должны понимать:

* зачем нужны битовые маски;
* почему нельзя без необходимости записывать регистры целиком;
* как установить, сбросить и проверить отдельный бит;
* почему почти все драйверы используют одинаковые побитовые операции;
* как читать примеры из Datasheet, не воспринимая их как набор магических символов.

---
